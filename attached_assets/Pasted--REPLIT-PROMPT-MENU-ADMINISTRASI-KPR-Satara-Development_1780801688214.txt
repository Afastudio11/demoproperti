# REPLIT PROMPT — MENU ADMINISTRASI KPR
## Satara Development Internal Dashboard

---

## KONTEKS

Dashboard internal Satara Development sudah berjalan dengan sidebar utama:
Executive Overview, Daftar Proyek, Akuisisi Lahan, Perencanaan, Legal & Perizinan,
Marketing, **Administrasi KPR** (← ini yang dibangun), Produksi, Serah Terima, Settings.

**Tugas:** Bangun seluruh halaman dan sub-menu untuk menu **Administrasi KPR**.
Divisi ini adalah jantung operasional developer subsidi. Uang tidak masuk saat booking —
uang masuk saat HT cair. Fungsi inti divisi adalah mengubah booking menjadi HT
melalui pipeline: Booking → Berkas → Setor Bank → OTS → SP3K → Akad → HT Cair.

### 1. ADMIN DASHBOARD
**Route:** `/administrasi`
**Fungsi:** Halaman pertama yang dibuka. Ringkasan harian untuk CEO dan Admin Manager.

**Komponen:**

**Pipeline Funnel (tampilkan sebagai visual funnel atau kanban horizontal):**

| Status | Jumlah Customer |
|--------|----------------|
| Booking / Minat | [count] |
| Proses Berkas | [count] |
| Berkas Lengkap | [count] |
| Setor Bank | [count] |
| OTS | [count] |
| SP3K | [count] |
| Akad | [count] |
| HT Cair | [count] |

Setiap kolom adalah count otomatis dari database. Klik angka → langsung ke halaman daftar customer dengan filter status tersebut.

**Metric cards (baris atas):**
- Total Customer Aktif (semua status sebelum HT)
- Total HT Cair Bulan Ini (Rp)
- Total HT Cair Tahun Ini (Rp)
- Bank Terbaik Bulan Ini (bank dengan akad terbanyak)
- Aging Warning (jumlah customer yang macet > threshold)
- Administration Health Score (angka/100)

**Panel Alerts:**
- Customer yang progress-nya macet > 14 hari di satu status
- Customer SP3K tapi bangunan belum ready (sinkron dari modul Produksi)
- Target akad bulan ini: [target] terealisasi [aktual] ([%])

**Data source:** Semua otomatis dari modul di bawah, tidak ada input manual.

### 3. DOCUMENT CHECKLIST
**Route:** `/administrasi/dokumen/:customer_id`

**Fungsi:** Tracking kelengkapan berkas per customer.

**Checklist dokumen standar Satara (hardcode sebagai default, bisa dikonfigurasi di Settings):**

**A. Data Pribadi:**
- KTP Pemohon
- KTP Pasangan (jika menikah)
- Kartu Keluarga (KK)
- NPWP (jika ada)
- Akta Nikah / Surat Cerai (jika berlaku)
- Akta Lahir Anak (jika diperlukan bank)
- Pas Foto 3x4 (2 lembar)

**B. Data Pekerjaan:**
- Slip Gaji 3 Bulan Terakhir
- SK Pengangkatan / SK Kerja
- Surat Keterangan Kerja dari Instansi
- Kartu Pegawai / ID Card
- SK Terakhir (untuk ASN, TNI, POLRI)

**C. Data Keuangan:**
- Rekening Koran / Buku Tabungan 3 Bulan
- Surat Keterangan Penghasilan (untuk wiraswasta)
- SIUP / NIB (untuk wiraswasta)

**D. Dokumen Pendukung:**
- Surat Pernyataan Belum Punya Rumah
- Surat Permohonan KPR
- Formulir Aplikasi Bank (tersedia dari bank)

**Form per dokumen:**
- Status: Belum Ada / Ada (Upload) / Sudah Disetor ke Bank
- Upload file (PDF/JPG)
- Catatan (jika ada masalah dokumen tertentu)

**Output kalkulasi:**
```
Document Completeness = (jumlah dokumen berstatus Ada) ÷ (total dokumen wajib) × 100%
```

Tampilkan: persentase kelengkapan + daftar dokumen yang masih kurang.

## UI/UX REQUIREMENTS

1. **Pipeline Kanban:** Di Admin Dashboard, tampilkan pipeline sebagai kartu kanban horizontal. Setiap kolom = satu status. Customer card bisa di-drag ke kolom berikutnya untuk update status (dengan konfirmasi modal).

2. **Status update cepat:** Di tabel Daftar Customer, setiap baris ada dropdown status yang bisa diubah langsung tanpa buka halaman detail. Setiap perubahan status otomatis tercatat di `customer_status_history`.

3. **Aging indicator:** Tampilkan badge hari di setiap customer card dan baris tabel. Warna: hijau (<7 hari), kuning (7-14 hari), oranye (14-30 hari), merah (>30 hari).

4. **Sinkron dengan Produksi:** Status bangunan dari modul Produksi harus muncul di halaman detail customer, terutama di SP3K Tracker. Tampilkan kolom "Progress Bangunan" dari data unit_progress_summary.

5. **Search global:** Di halaman Daftar Customer, sediakan search bar yang bisa mencari berdasarkan nama, blok, nomor telepon, dan nama PIC.

6. **Export Excel:** Halaman Daftar Customer harus bisa di-export ke Excel dengan format yang menyerupai struktur asli file RINGKASAN_KONSUMEN_SN_.xlsx (per sheet per proyek).
