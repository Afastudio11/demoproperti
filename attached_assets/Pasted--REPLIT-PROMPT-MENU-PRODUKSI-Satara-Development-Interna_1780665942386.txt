### 4. MANAJEMEN SUBKON

#### 4a. Daftar Kontrak Subkon
**Route:** `/produksi/subkon/kontrak`

**Form Tambah Kontrak:**

| Field | Tipe | Keterangan |
|-------|------|-----------|
| Nama subkon | Text | Contoh: DG IWAN, DG ZUL, DG DANDI |
| Proyek & tahap | Select | |
| Jumlah unit dikerjakan | Number | |
| Nilai kontrak per unit | Number (Rp) | Input nominal per unit, contoh: Rp 16.500.000 |
| Total nilai kontrak | Auto (Rp) | = nilai per unit × jumlah unit |
| Retensi per unit | Number (Rp) | Nominal tetap, contoh: Rp 500.000 per unit |
| Total retensi | Auto (Rp) | = retensi per unit × jumlah unit |
| Nilai bersih dapat dibayar | Auto (Rp) | = total kontrak − total retensi |
| Tanggal mulai | Date | |
| Tanggal target selesai | Date | |
| Masa pemeliharaan (bulan) | Number | Retensi baru bisa dicairkan setelah N bulan sejak unit 100%. Default: 3 bulan |

**Catatan penting — mekanisme retensi Satara:**
Retensi adalah **nominal tetap per unit** (bukan persentase), dan baru bisa dicairkan setelah masa pemeliharaan berakhir. Sistem harus:
1. Menahan retensi dari setiap termin secara proporsional sampai unit 100%.
2. Mencatat tanggal unit selesai 100% sebagai titik mulai masa pemeliharaan.
3. Menampilkan status retensi per kontrak: Ditahan / Masa Pemeliharaan (countdown hari) / Siap Cair.
4. Memberi notifikasi ke finance saat retensi sudah boleh dicairkan.

**Contoh data aktual dari file Laporan_subkon.xlsx yang harus bisa diinput:**
- DG IWAN: 5 unit, Rp 16.500.000/unit, total Rp 82.500.000, retensi Rp 500.000/unit
- DG ZUL: 3 unit, Rp 16.500.000/unit, total Rp 49.500.000, retensi Rp 500.000/unit
- DG DANDI: 6 unit, Rp 16.500.000/unit, total Rp 99.000.000, retensi Rp 500.000/unit
- DG RAJA: 5 unit, Rp 16.500.000/unit, total Rp 82.500.000, retensi Rp 500.000/unit
- DG DAHLAN: 5 unit, Rp 16.500.000/unit, total Rp 82.500.000, retensi Rp 500.000/unit
- DG AKBAR: 2 unit, Rp 16.500.000/unit, total Rp 33.000.000, retensi Rp 500.000/unit
- DG NUDING: 5 unit, Rp 16.500.000/unit, total Rp 82.500.000, retensi Rp 500.000/unit

Nilai kontrak per unit dan retensi per unit sepenuhnya **custom per proyek** — bisa berbeda antar tahap atau antar proyek (Barru, Villa Sinoa, dll bisa punya nilai berbeda).

**Tampilan daftar kontrak:**
- Tabel: nama, unit, nilai/unit, total kontrak, retensi/unit, total retensi, total terbayar (di luar retensi), retensi tertahan, status retensi, status kontrak
- Status kontrak otomatis: Aktif / Selesai / Overdue
- Status retensi otomatis: Ditahan / Masa Pemeliharaan [sisa N hari] / Siap Cair / Sudah Cair

#### 4b. Termin Payment System
**Route:** `/produksi/subkon/termin`

**Ini adalah inti sistem pembayaran Satara. Pembayaran dilakukan tanggal 15 dan 30 berdasarkan progress fisik.**

**Form input termin:**

| Field | Tipe | Keterangan |
|-------|------|-----------|
| Nama subkon | Select | |
| Periode termin | Select | Tanggal 15 / Tanggal 30 |
| Bulan & tahun | Month picker | |
| Progress termin sebelumnya (%) | Number | Auto-fill dari termin sebelumnya |
| Progress termin saat ini (%) | Number | Input aktual |

**Kalkulasi otomatis (tampilkan setelah input):**
```
Velocity                    = Progress Saat Ini − Progress Termin Sebelumnya

Hak Bayar Bruto             = (Progress Saat Ini − Total % sudah dibayar) × Total Nilai Kontrak
Retensi Proporsional        = Retensi Per Unit × Unit yang progress-nya tercapai termin ini
                              (Retensi ditahan sampai unit 100% dan masa pemeliharaan selesai)
Tagihan Bersih Termin Ini   = Hak Bayar Bruto − Retensi Proporsional

Nilai Bersih Total Dapat Dibayar = Total Kontrak − Total Retensi
Sisa yang Belum Dibayar          = Nilai Bersih Total − Akumulasi Pembayaran Sebelumnya
```

**Contoh kalkulasi (tampilkan sebagai ilustrasi di halaman):**
```
Subkon DG IWAN — 5 unit
Nilai Kontrak per Unit      : Rp 16.500.000
Total Nilai Kontrak         : Rp 82.500.000
Retensi per Unit            : Rp 500.000
Total Retensi               : Rp 2.500.000
Nilai Bersih Dapat Dibayar  : Rp 80.000.000

Progress Termin Sebelumnya  : 30%
Progress Termin Saat Ini    : 47%
Velocity                    : 17%

Hak Bayar Bruto             : 17% × Rp 82.500.000 = Rp 14.025.000
Retensi Termin Ini          : 17% × Rp 2.500.000  = Rp 425.000
Tagihan Bersih Termin Ini   : Rp 14.025.000 − Rp 425.000 = Rp 13.600.000

Status Retensi              : Ditahan (unit belum 100%)
Total Retensi Tertahan s/d sekarang: Rp 425.000 + akumulasi termin sebelumnya
```

**Mekanisme pencairan retensi (terpisah dari termin biasa):**
- Setelah semua unit subkon tersebut mencapai 100% progress, sistem otomatis mencatat tanggal selesai.
- Masa pemeliharaan berjalan: countdown N bulan (sesuai kontrak, default 3 bulan).
- Setelah masa pemeliharaan berakhir, sistem membuat tagihan retensi otomatis.
- Tagihan retensi masuk ke antrian Approval Pembayaran dengan tipe "Pencairan Retensi".
- Finance mencairkan total retensi tertahan sekaligus.

**Output per subkon:**
- Tagihan Bersih Termin Ini (Rp)
- Total Sudah Dibayar (di luar retensi) (Rp)
- Total Retensi Tertahan (Rp)
- Status Retensi: Ditahan / Masa Pemeliharaan [sisa N hari] / Siap Cair
- Sisa Kontrak yang Belum Dibayar (Rp)

**Histori pembayaran (dari data aktual file Laporan_subkon.xlsx):**
Sistem harus menyimpan setiap pembayaran dengan kolom: tanggal pembayaran, jumlah, termin ke-berapa.

| A3 | 60% | Proses Bank | On Progress | Atap | - |

**Status Administrasi diambil dari modul Administrasi KPR** (sinkron otomatis).
**Status Bangunan** dihitung dari progress unit:
- Ready Akad: progress ≥ 100% dan QC Score ≥ 90%
- Belum Ready: progress < 100% atau QC Score < 90%
- On Progress: progress > 0% dan < 100%

**Kalkulasi HT Tertahan:**
```
HT Tertahan = Nilai HT unit × jumlah unit SP3K yang belum ready akad
```

**Metric cards di atas:**
- Unit SP3K belum ready akad: [jumlah]
- Estimasi selesai rata-rata: [hari]
- Total HT tertahan: [Rp]

**Unit Priority System:**
Sistem otomatis mengurutkan unit berdasarkan prioritas pengerjaan:
1. Sudah SP3K (prioritas tertinggi)
2. Proses Bank
3. Sudah Booking
4. Stok biasa

Tampilkan urutan prioritas ini sebagai daftar di panel kanan.

### 8. ANALISIS PRODUKTIVITAS

#### 8a. Velocity Analysis
**Route:** `/produksi/analitik/velocity`

**Tampilan:**
```
Velocity = Progress Termin Saat Ini − Progress Termin Sebelumnya
```
- Tabel: subkon, velocity termin 1, velocity termin 2, velocity termin 3, trend (naik/turun)
- Bar chart: velocity per subkon per termin
- Highlight: Subkon Tercepat (hijau) dan Subkon Terlambat (merah)

#### 8b. Baseline Progress Tracker
**Route:** `/produksi/analitik/baseline`

**Tampilan:**
- Tabel per unit: progress aktual vs baseline (dari tabel standar 8 minggu)
- Status: Ahead / On Track / Warning / Critical
- Gantt mini per unit (opsional jika performa memungkinkan)

#### 8c. Cost to Complete
**Route:** `/produksi/analitik/cost-to-complete`

**Form input per unit:**

| Field | Tipe |
|-------|------|
| Progress saat ini (%) | Auto dari checklist |
| Biaya terpakai hingga kini (Rp) | Number |
| Nilai kontrak subkon (Rp) | Auto dari kontrak |

**Kalkulasi:**
```
Biaya Standar Total    = Nilai Kontrak
Biaya Per % Progress   = Biaya Standar Total ÷ 100
Estimasi Sisa Biaya    = (100% − Progress Aktual) × Biaya Per % Progress
Status Budget:
  - Aman: biaya terpakai ≤ (progress × biaya standar)
  - Warning: biaya terpakai > (progress × biaya standar) + 10%
  - Overbudget: biaya terpakai > (progress × biaya standar) + 20%
```

**Output CEO:**
- "Estimasi dana yang masih dibutuhkan untuk menyelesaikan Tahap [X]: Rp [Y]"

#### 8d. Cashflow Impact of Delay
**Route:** `/produksi/analitik/cashflow-impact`

**Tampilan:**
- Tabel: unit, status admin (SP3K/Proses/dll), delay dari target (hari), HT tertahan (Rp)
- Total HT tertahan karena progress bangunan (Rp) — metric card besar
- Narasi otomatis: "Keterlambatan produksi saat ini menahan HT senilai Rp [X], yang berdampak pada pembayaran cicilan KPP bulan [Y]."

#### 8e. Productivity Score
**Route:** `/produksi/analitik/produktivitas`

**Kalkulasi skor per subkon (otomatis dari semua modul):**

| Komponen | Bobot | Sumber Data |
|----------|-------|-------------|
| Velocity | 40% | Modul 8a |
| Progress Achievement | 25% | Modul 2c |
| QC Score | 20% | Modul 6a |
| Rework (terbalik: 100 − rework rate) | 10% | Modul 6b |
| Administrasi (kelengkapan dokumen) | 5% | Manual input |

```
Productivity Score = (Velocity × 0,4) + (Achievement × 0,25) + (QC × 0,2) + (Rework × 0,1) + (Admin × 0,05)
Normalisasi ke skala 0-100
```

**Kategori:**
- 85-100: Excellent (hijau)
- 70-84: Good (kuning)
- <70: Poor (merah)

#### 8f. Subkon Eligibility Score
**Route:** `/produksi/analitik/eligibilitas`

**Kalkulasi untuk menentukan apakah subkon layak diberi pekerjaan tahap berikutnya:**

| Komponen | Bobot |
|----------|-------|
| Kecepatan progress | 30% |
| Kualitas pekerjaan (QC) | 25% |
| Efisiensi material (variance) | 20% |
| Rework rendah | 15% |
| Kepatuhan administrasi | 10% |

**Output per subkon:**

| Subkon | Score | Rekomendasi |
|--------|-------|-------------|
| DG IWAN | 92 | Tambah unit |
| DG ZUL | 84 | Lanjut |
| DG DAHLAN | 71 | Batasi unit |
| DG NUDING | 58 | Evaluasi / Stop |

#### 8g. Production Forecast
**Route:** `/produksi/analitik/forecast`

**Kalkulasi:**
```
Estimasi Selesai = Progress Saat Ini + (Velocity per Termin × Jumlah Termin Tersisa)
Termin Tersisa   = (100% − Progress Aktual) ÷ Velocity per Termin
Estimasi Tanggal = Tanggal Hari Ini + (Termin Tersisa × 15 hari)
```

**Tampilan:**
- Tabel per tahap: unit aktif, progress saat ini, velocity rata-rata, estimasi selesai (tanggal)
- Alert: "Tahap [X] diperkirakan selesai [tanggal]. Jika velocity turun ke [Y]%, estimasi bergeser ke [tanggal]."

### 9. CONSTRUCTION HEALTH SCORE
**Route:** `/produksi/health`

**Kalkulasi skor kesehatan proyek (per proyek aktif):**

| Komponen | Bobot | Sumber Data |
|----------|-------|-------------|
| Progress vs Target | 25% | Modul 2 |
| Timeline (tidak delay) | 20% | Modul 8g |
| QC Score rata-rata | 20% | Modul 6 |
| Material Efficiency | 15% | Modul 5f |
| Payment Accuracy (subkon dibayar tepat) | 10% | Modul 4b |
| Fasum Progress | 10% | Modul 3 |

```
Construction Health Score = Σ (komponen × bobot)
Skala 0-100
```

**Status:**
- 85-100: SEHAT (hijau)
- 70-84: WASPADA (kuning)
- < 70: BERMASALAH (merah)

**Tampilan:**
- Satu score besar per proyek
- Breakdown radar chart 6 komponen
- Narasi otomatis: "Proyek [X] dalam kondisi [STATUS]. Area yang perlu perhatian: [komponen terendah]."

-- Unit per proyek
project_units (

  unit_id uuid REFERENCES project_units(id),
  total_progress numeric,   -- sum bobot item yang selesai
  week_number integer,      -- minggu ke-berapa sejak mulai
  baseline_target numeric,  -- target baseline minggu tersebut
  status text,              -- Ahead/On Track/Warning/Critical
  updated_at timestamptz

  notes text,
  photo_urls text[],

  updated_at timestamptz

  total_retention numeric,       -- auto: retention_per_unit × unit_count
  net_payable_value numeric,     -- auto: contract_value − total_retention
  maintenance_months integer DEFAULT 3, -- masa pemeliharaan dalam bulan
  start_date date,
  target_end_date date,
  actual_completion_date date,   -- diisi sistem saat semua unit subkon = 100%
  retention_release_date date,   -- auto: actual_completion_date + maintenance_months

)

## UI/UX REQUIREMENTS

1. **Nested sub-menu:** Saat klik Produksi di sidebar, tampilkan sub-menu collapsible. Sub-menu dengan item tambahan (Logistik, QC, Analitik) tampil dengan indentasi kedua.

2. **Project context selector:** Di bagian atas setiap halaman, ada dropdown selector proyek aktif. Pilihan proyek tersimpan di session sehingga tidak perlu dipilih ulang di setiap halaman.

3. **Status dots:** Setiap sub-menu di sidebar punya indikator warna:
   - Abu-abu: belum ada data
   - Hijau: normal
   - Kuning: perlu perhatian
   - Merah: ada masalah / alert aktif

4. **Photo evidence:** Setiap form yang membutuhkan foto menggunakan komponen upload dengan preview thumbnail. Foto disimpan ke Supabase Storage. Tampilkan foto dalam grid 3 kolom (before/during/after).

5. **Role-based actions:** Tombol Approve/Reject/Hold pada alur pembayaran hanya muncul sesuai peran user yang login (pengawas, qc_officer, production_manager, finance, ceo).

6. **Kalkulasi real-time:** Semua kalkulasi otomatis (velocity, tagihan layak bayar, QC score, health score) harus terupdate langsung saat data berubah, tanpa reload halaman.

7. **Print/Export:** Halaman Termin Payment System harus bisa dicetak / export PDF sebagai dokumen tagihan resmi ke finance.

8. **Mobile-friendly:** Halaman Update Progress Unit dan Input Material Keluar harus bisa digunakan dari HP di lapangan (touch-friendly, font besar, form sederhana).

9. **Number format:** Semua rupiah: `Rp 1.250.000`. Semua persentase: `42,0%`. Semua tanggal: `15 Januari 2026`.

10. **Empty state:** Setiap halaman yang kosong tampilkan ilustrasi + tombol CTA. Contoh: "Belum ada data progress. Mulai input checklist unit."
